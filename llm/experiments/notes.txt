  #### 1. File 1: model_llama.py (Pure LLaMA-3 Dense Architecture)

  • Design Philosophy: 100% self-contained (~150 lines), zero MoE branches, matches
  official Hugging Face / Meta LLaMA-3 naming conventions.
  • Component Specs:
    @dataclass
    class LlamaConfig:
        vocab_size: int = 16384
        n_layer: int = 12
        d_model: int = 512
        n_head: int = 8
        n_kv_head: int = 2              # 4:1 Grouped Query Attention (GQA)
        block_size: int = 1024
        intermediate_size: int = 3072   # SwiGLU hidden dim (approx 8/3 * d_model)
        rms_norm_eps: float = 1e-6
        rope_base: float = 10000.0
        attn_impl: str = "sdpa"

  • Classes:
      • LlamaRMSNorm: Exact root-mean-square normalization.
      • LlamaRotaryEmbedding + apply_rotary_emb: Standard RoPE implementation.
      • LlamaAttention: GQA with FlashAttention / SDPA.
      • LlamaMLP: Pure SwiGLU (W₂(silu(W₁(x)) × W₃(x))).
      • LlamaDecoderLayer: Residual Pre-RMSNorm Attention + MLP.
      • LlamaForCausalLM: Embedding + Layers + Final RMSNorm + Tied LM Head + Cross
      Entropy Loss.

  #### 2. File 2: model_deepseek.py (Pure DeepSeek-MoE Architecture)

  • Design Philosophy: 100% self-contained (~220 lines), dedicated sparse mixture-of-
  experts logic matching DeepSeek-V2/V3.
  • Component Specs:
    @dataclass
    class DeepSeekConfig:
        vocab_size: int = 16384
        n_layer: int = 12
        d_model: int = 512
        n_head: int = 8
        n_kv_head: int = 2
        block_size: int = 1024
        moe_intermediate_size: int = 1024 # Hidden dim per expert
        n_routed_experts: int = 8         # Total routed experts (E)
        num_experts_per_tok: int = 2      # Top-K active routed experts
        n_shared_experts: int = 1         # Isolated shared expert (DeepSeek innovation)
        n_dense_first: int = 1            # Layer 0 stays dense for numerical stability
        aux_loss_coef: float = 0.01       # Load balancing loss coefficient
        router_z_loss_coef: float = 1e-3  # Router logits stabilization loss
        attn_impl: str = "sdpa"

  • Classes:
      • DeepSeekRMSNorm & DeepSeekRotaryEmbedding & DeepSeekAttention.
      • DeepSeekExpert: Dedicated SwiGLU expert block.
      • DeepSeekRouter: Top-K softmax routing with probability renormalization,
      computing both auxiliary load-balancing loss and router z-loss.
      • DeepSeekMoE: Isolated Shared Experts + Top-K Routed Experts dispatch.
      • DeepSeekDecoderLayer: Hybrid dense/MoE layer.
      • DeepSeekForCausalLM: End-to-end model returning loss = ce_loss + aux_loss +
      z_loss and expert distribution statistics for logging.

  #### 3. How train.py & generate.py will be adapted

  • In train.py:
      • --model llama → builds LlamaForCausalLM(LlamaConfig(**PRESETS[args.preset]))
      • --model deepseek → builds DeepSeekForCausalLM(DeepSeekConfig(**PRESETS[args.
      preset]))
      • Cleans up the training loop: metrics like max_load, min_load, and load_entropy
      are only tracked and logged when training --model deepseek, keeping the terminal
      log clean for LLaMA.
  • In generate.py:
      • Automatically detects model_type: "llama" or "deepseek" stored in ckpt.pt and
      initializes the correct model class dynamically

### 1. Run small on GPU (RTX 5060 Ti / ≤ 8GB Target)

  #### A. Preset "tiny" (Smoke test & learning pipeline)

  • Model Size: ~10M–15M total parameters.
  • VRAM Consumption: ≈ 1.0 – 1.5 GB.
  • Impact: Runs extremely fast, very low power draw, and will not stress your GPU at all.

  #### B. Preset "small" with --model dense

  • Model Size: ~75M parameters.
  • VRAM Consumption: ≈ 3.0 – 4.0 GB with --batch_size 16 --grad_accum 4.
  • Impact: Well below your 8 GB limit with plenty of headroom.

  #### C. Preset "small" with --model moe

  • Model Size: ~190M total parameters (~75M active parameters per token).
  • VRAM Consumption:
      • Default flags (--batch_size 16): ≈ 7.2 – 7.8 GB (very close to the 8 GB edge, could trigger OOM if other applications use VRAM).
      • Optimized for ≤ 8GB: Set --batch_size 8 --grad_accum 8 or --batch_size 4 --grad_accum 16.
          • This cuts activation memory in half, keeping total VRAM around 5.0 – 5.8 GB.
          • It keeps the exact same effective batch size (65, 536 tokens/step).

  ### 1. Step-by-Step Guide to Run

  #### Step 1: Quick Data Preparation

  Instead of tokenizing 300M tokens right away (which takes longer to stream), start with a quick 30M token set for your first experiments:

    python prepare_data.py --out data/fwedu --max_tokens 30000000 --val_tokens 2000000

  #### Step 2: Smoke Test (tiny preset, ~1.2 GB VRAM)

  Test the entire pipeline in 2–3 minutes:

    python train.py --preset tiny --model moe --batch_size 16 --grad_accum 2 --max_steps 500 --eval_interval 100 --out_dir runs/tiny_moe

  Check:

  • Initial cross-entropy loss should start around ln(16384) ≈ 9.7 and decrease steadily.
  • mem reported in terminal should be < 1.5 GB.

  #### Step 3: Test Text Generation

    python generate.py --ckpt runs/tiny_moe/ckpt.pt --tok data/fwedu/tokenizer.json --prompt "Once upon a time"

  #### Step 4: Scale to Small Model (Keeping VRAM Safely Under 6 GB)

  To train the 190M MoE model without maxing out your 8 GB VRAM:

    python train.py --preset small --model moe --batch_size 8 --grad_accum 8 --max_steps 10000 --out_dir runs/small_moe

  (Or for dense baseline):

    python train.py --preset small --model dense --batch_size 8 --grad_accum 8 --max_steps 10000 --out_dir runs/small_dense

  ### 4. Important Tips & Caveats

  1. Avoid --compile on MoE:
  In train.py:38, do not use --compile with --model moe. The dynamic token dispatch loop (counts.tolist() in model.py:156) causes PyTorch
  graph breaks. --compile works well with --model dense.
  2. Hard-capping VRAM allocation (Optional):
  If you want PyTorch to strictly never allocate more than, for example, 7 GB (leaving 1 GB free for display/system), you can add this line
  at the top of train.py:52:
    torch.cuda.set_per_process_memory_fraction(0.85, 0) # Caps PyTorch at 85% of VRAM

  3. PyTorch Version:
  sdpa_attn uses enable_gqa=True, which is supported in PyTorch 2.5+. Make sure your active venv has PyTorch 2.5 or newer.
